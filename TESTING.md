# Deal-Prep Copilot – Testing Strategy

Every main component has tests, run after every change. Section numbers like §7 in the log rows refer to the 12 briefing sections.

## 1. Principles

- Every main component gets tests in the phase that builds it. Run the suite after every change.
- External services (LLM, embeddings, Tavily) are **mocked in unit tests**. Integration and eval runs use the real services and are run on purpose, not on every change (they cost money).
- No real or sensitive organization data in tests without approval. Use `rag_knowledge_base/` and the sample CRM CSV.
- Tests never print or log secrets.

## 2. Test levels

### 2.1 Unit tests (`pytest`, fast, offline)
- Config loading and missing-variable errors.
- Permission helpers and role checks.
- Extractors (PDF/DOCX/TXT/MD/CSV) on small fixture files, including a Hebrew sample.
- Chunkers: heading paths, overlap, CSV row groups keep the header and the correct row range.
- RRF merge logic (pure function version), dedup, URL normalization, date parsing.
- Source tiering rules (D21) and claim confidence rules.
- Agent data contracts: valid/invalid payloads.
- Orchestrator with mocked agents: parallel stages, iteration bound, stage failure → partial, cancel → stop.
- Quality checks on hand-made briefings.

### 2.2 Integration tests (dev Supabase project, marked `@pytest.mark.integration`)
- `db_setup.py` connection test.
- RLS isolation: user A can't read user B's runs, briefings, versions, sources or feedback. Regular user can't write to `documents`.
- Invite flow. Signup disabled.
- Ingestion end to end: upload → Indexed. Replace → old version no longer returned. Delete → no chunks returned, historical briefing still shows its snippet.
- `hybrid_search` returns expected documents for known queries.
- Tavily adapter live smoke test (1–2 credits).
- One full research run on a test company (Quick depth).
- PDF export: Hebrew and English render without broken RTL (visual check + text extraction check).

### 2.3 Agent and retrieval evaluation (`evals/`)
A small, versioned set of representative cases. Re-run after any change to prompts, code or model.

| Area | Cases | Metrics |
|---|---|---|
| KB retrieval | 15–20 queries (He + En) with expected documents from `rag_knowledge_base/` | Hit@5, MRR |
| External research | 5–8 companies (Israeli + international, public + private) | relevant sources found, duplicates, date correctness, Tier 1–2 share |
| Competitor analysis | same companies | competitors identified vs reference list, unsupported advantage claims (should be 0) |
| Strategic analysis | same companies × Sales / Partnership | rubric 1–5: relevance to goal, facts vs analysis separated, rationale for importance |
| Final briefing | same | sections present or marked missing, % important claims with sources, language correctness, rubric 1–5 overall |
| Cost / time | every eval run | tokens, Tavily credits, $ estimate, duration per depth |

Rubric scoring: manual review first. An LLM-as-judge with a fixed rubric may be added later (no evaluation platform needed).

## 3. MVP acceptance checklist
Planned: each MVP success criterion with the test or demo step that proves it.
